## Quickstart

Prerequisites: Rust 1.85 or newer (stable toolchain, see `rust-toolchain.toml`), on macOS or Linux. The linker produces arm64 macOS binaries from any of these hosts.

```sh
git clone https://github.com/elcoosp/peregrine
cd peregrine
cargo build --release --locked
cargo test --workspace --locked
```

Link a hello-world against the libSystem `.tbd` stub that ships with the macOS SDK:

```sh
clang -arch arm64 -c hello.c -o hello.o      # Apple clang on macOS, or osxcross on Linux
./target/release/pgr -o hello hello.o -l System -L stubs -platform_version macos 12.0 14.0
./target/release/pgr-verify hello --strict
```

`-L stubs` points at a directory of `.tbd` stubs (on macOS: the SDK's `usr/lib`). The driver searches `-L` dirs, then `/usr/lib`; `.tbd` stubs, Mach-O dylibs and static `.a` archives are all accepted library forms.

The same surface scales to real links — static archives with lazy member pull, dead-code stripping, identical code folding, and a relink cache:

```sh
./target/release/pgr -o app main.o -lgreet -L libs \
    -dead_strip -icf=safe -cache .pgr-cache
./target/release/pgr-verify app --strict
```

Every linked image passes `pgr-verify --strict` in the repo's own end-to-end gates — the e2e suite links fixtures, walks the chained fixups, and recomputes signatures before asserting anything else.

## Features

- **ld64-compatible driver surface.** `-dylib`/`-bundle` outputs, two-level namespace, `-weak_library`, `-rpath`, export filters, `-framework`/`-F`, `-filelist`, `-all_load`/`-force_load` and more; every row is tracked with a fixture in [docs/COMPAT.md](docs/COMPAT.md), and unsupported flags fail with actionable errors instead of being silently dropped.
- **Correctness gated by a built-in verifier.** `pgr-verify` re-reads each image: full dyld chain-walk simulation of `LC_DYLD_CHAINED_FIXUPS`, SHA-256 signature page-hash recompute, 16 KiB segment congruence, export-trie walks (including re-export nodes), `B`/`BL` branch-range decoding, and a dylib+executable pair gate. It ships as a CLI (`--strict`, `--json`) and as a library.
- **Size optimizations with recorded evidence.** `-dead_strip` mark-sweep over symbol-boundary atoms; `-icf=safe`/`-icf=all` identical code folding via color refinement; cross-input `__cstring` merging; ranlib-guided lazy archive member pull. Numbers and methods are recorded in [docs/BENCHMARKS.md](docs/BENCHMARKS.md) (e.g. the dead-strip bench link runs 1.9x faster than the unstripped link on a 50%-dead corpus).
- **Deterministic output.** Double links are byte-identical (a CI-level gate), the parallel fused tile emit is byte-identical to the reference emit kept in-tree, and nothing reads hash iteration order — parallel schedules change who computes a result, never the result.
- **Safe, panic-free parsing.** The workspace forbids `unsafe` (`unsafe_code = "forbid"`) and carries no lint suppressions; parsers return typed errors and never panic. Nightly cargo-fuzz targets (`parse_any`, `parse_tbd`, `verify_image`, `link_object`, `link_record`, `dyld_info_streams`, `cache_entries`) plus stable proptests keep that honest.
- **Relink caching.** Content-addressed, checksum-framed caches for parsed objects and frozen `.tbd` export sets (`-cache <dir>`, `PGR_CACHE_DIR`, `-no_cache`); cached and uncached outputs are byte-identical, and corruption falls back to a silent re-parse.
- **Resident relinking (M8).** `pgr -resident` routes a link through the optional `pgrd` daemon, which keeps the parsed state of unchanged inputs (POIs), the input bytes and the emit buffer across links: a warm relink transfers manifests only, skips the parse (hit-counted), and reuses its output buffer. Optional and transparent by contract — the daemon is started on demand, idles out, and every failure silently falls back to the one-shot link. Resident output is byte-identical to the one-shot link (a test gate, not a promise): the daemon never writes the output — the client does, through the normal atomic-rename path — so a crash or restart can never corrupt an image.
- **In-place incremental relinking (M9).** `pgr -incremental` records the link's emit plan next to the output (`<output>.pgr-inc`) and, on the next link, patches only the changed 16 KiB tiles into a copy-on-write clone of the previous output (`fclonefileat` on APFS), rebuilds page 0 with the fresh `LC_UUID`, and re-signs from the merged page-hash table — recorded hashes for clean pages, recomputed for dirty ones. Slack-anchored layout (the M8-c policy, anchored cross-link) keeps a changed section where it was, and the §7.3 fallback ladder now executes its middle rung: a section that overflows its anchor within the relayout bound holds its base while everything behind it shifts, and the relayout tier patches the moved suffix (clone resized, re-signed at the moved signature boundary) instead of re-running the full link — an outgrown `__LINKEDIT` reservation moves the boundary the same way. Anything else (or any record problem) still falls back to the full link silently. The engine's contract — the patched file is byte-identical to the full fused emit of the same plan — is a test gate, and `-incremental-verify` re-proves it per link plus a strict `pgr-verify` pass. One-function edits patch ~1% of an 8 MiB image's bytes, and a slack-overflowing edit patches ~13% through the relayout tier (docs/BENCHMARKS.md). The record's v5 section also carries the Pass-2 resolution snapshot, so a relink's symbol resolution plans through the recorded decisions (recorded winners ride verbatim, seed-touched names replay the precedence rules) and falls back to the full resolve whenever the input-file list or dylib export surface moves. With `-resident` on, the same cycle runs through the daemon: the previous record and output ride the wire, the relink pipeline reuses the session's parsed-object images, the ladder patches in memory, and the client writes the file — byte-identical to the one-shot cycle (a test gate), with every fallback re-recording so the cycle never stalls. The daemon also *serves* the `-incremental-verify` audit (protocol v4): the session audits its in-memory patch against the reference emit and hands the verdict across the wire, healing a divergence in memory before it ships — the client refuses to write a failing verdict, so the audited relink runs warm instead of standing down to a second cold pipeline. And the session now *holds* the output across links (protocol v5, the §7.2 output-residency rung): every served image becomes resident output state keyed by its content hash, so the previous output stops re-crossing the wire, a patched relink's reply is the changed 16 KiB-tile stream instead of the image (an untouched relink ships nothing), and the client hash-verifies its tile replay before the atomic write — the last full-image wire crossing in a warm cycle is gone.
- **Current Mach-O coverage.** `DYLD_CHAINED_PTR_64_OFFSET` chained fixups with a classic `LC_DYLD_INFO_ONLY` opcode fallback for pre-chained deployment targets, full export tries with re-exports, arm64 GOT/stub synthesis, branch veneers for beyond-±128 MiB calls, ad-hoc signing, `.tbd` v3/v4, and BSD/GNU long-name archives. Chained fixups serve macOS 12.0+, iOS 15.0+, tvOS 15.0+, watchOS 8.0+ and visionOS 1.0+ targets — the per-platform floor (`pgr_core::layout::chained_fixups_min_minos`) falls back to the classic opcode streams below it, changing the encoding, never the fixups. Mach-O constants are cross-checked against the `object` crate in CI.

## How it works

Peregrine is a six-pass pipeline split across six crates. `pgr-driver` maps inputs (Pass 0) and drives the loop; `pgr-format` provides zero-copy, bounds-checked parsing of Mach-O, archives, `.tbd` stubs, chained fixups and signature blobs; `pgr-core` runs Passes 1–3 (LPT-scheduled parallel parse and interning, two-level symbol resolution with archive liveness, layout with `__got`/`__stubs` synthesis, ICF, dead-strip and fixup planning); `pgr-emit` runs Passes 4–5, where parallel 16 KiB tiles copy runs, apply relocations, encode chain words, place `__LINKEDIT` and hash signature pages in one pass over each byte, then a 4-writer `pwrite` pool flushes the file. `pgr-verify` closes the loop by treating the output as a hostile third-party image and validating it against the contract dyld will enforce at load time. `pgr-daemon` (M8) wraps the same pipeline in a resident server: unchanged inputs keep their parsed state across links, with byte-identity to the one-shot link gated by tests.

| Crate | Role |
|---|---|
| `pgr-driver` | the `pgr` CLI binary: option parsing, input classification, the Pass 0–5 loop |
| `pgr-format` | zero-copy Mach-O primitives: headers, load commands, symtab, relocations, chained fixups, export tries, `.tbd` v3/v4, `!<arch>` archives, signature blobs |
| `pgr-core` | Passes 1–3: interning, two-level resolution, layout, ICF, dead-strip, thunks, dyld-info planning, caches, the M8 reverse reference index / insertion-stable import table / slack policy |
| `pgr-emit` | Passes 4–5: fused tile emit, relocation application, ad-hoc signature, concurrent writer — and the M9 incremental engine (record, plan, clone-and-patch) |
| `pgr-verify` | the read-side verifier: library and `pgr-verify` CLI |
| `pgr-daemon` | the M8 resident link server: the `pgrd` daemon, its wire protocol (v6), the persistent session (POIs + bytes + emit buffer + the §7.2 resident output state), the client `pgr -resident` speaks, and the M9 audit the session serves |
| `pgr-fixtures` | deterministic Mach-O object and archive builders shared by tests, benches and the fuzz corpus |

## Usage

Key driver flags (full surface: `pgr --help`):

| Group | Flags |
|---|---|
| Output kind | `-o`, `-static`, `-dylib`, `-bundle`, `-r` (relocatable, M10), `-e` |
| Platform targeting (M10) | `-platform_version macos\|ios\|tvos\|watchos\|visionos <min> <sdk>` (SDK ≥ deployment target; the per-platform chained-fixups floor picks the fixup encoding) |
| Inputs and search | object/`.a`/`.tbd`/`.dylib` paths, `-l`, `-L`, `-filelist path[,dir]`, `-framework`/`-F`, `-all_load`, `-force_load`, `-u` |
| Symbol binding | `-flat_namespace`, `-undefined error\|dynamic_lookup`, `-weak_library`, `-rpath` |
| Dylib metadata | `-install_name`, `-current_version`, `-compatibility_version`, `-reexport_library`, `-exported_symbols_list`, `-unexported_symbols_list` |
| Codegen and size | `-dead_strip`, `-icf=safe\|all\|none`, `-fixup_chains`/`-no_fixup_chains`, `-fixup_chains_format offset64\|arm64e` (M10 rung 4: the chain word family; the default stays the M2 encoding), `-adhoc`/`-no_adhoc`, `-segalign`, `-headerpad`, `-sectcreate` |
| Caching and jobs | `-cache <dir>`, `-no_cache`, `PGR_CACHE_DIR`, `-cache_max <bytes>`, `PGR_CACHE_MAX`, `PGR_JOBS` |
| Incremental mode (M9) | `-incremental`, `-no_incremental`, `-incremental-verify` (daemon-served under `-resident`), `PGR_INCREMENTAL_RECORD`, `PGR_INCREMENTAL_DEBUG` |
| Resident mode (M8) | `-resident`, `-resident_socket <path>`, `PGR_DAEMON_SOCK`, `PGR_RESIDENT_DEBUG`; the `pgrd` daemon: `--socket`, `--idle-secs`, `--shutdown` |

Environment: `PGR_JOBS` sizes the shared compute pool (default: available parallelism); `PGR_LLD64=/path/to/ld64.lld` enables the golden harness that compares Peregrine's bind semantics slot-for-slot against `ld64.lld` (skipped when lld is absent); `PGR_TRACING=1` installs a tracing subscriber in the consumer examples (the binaries install one under their debug envs — the spans are inert without a subscriber).

As a library, the crates are path dependencies (not published to crates.io — `publish = false` in each manifest), so reference them by path or git. The verifier is the natural entry point for tooling:

```rust
let report = pgr_verify::verify(&bytes, &pgr_verify::Options::default());
for issue in &report.issues {
    println!("{:?} [{}] {}", issue.severity, issue.code.as_str(), issue.message);
}
```

> [!TIP]
> When auditing a linker's output, start from `pgr-verify <image> --json`: the machine-readable report names every issue with a stable code (`fixups_chain`, `export_trie`, `branch_range`, `signature_hash_mismatch`, ...), so CI jobs can gate on specific violations instead of grepping text.

Compatibility is a tracked checklist rather than a promise: [docs/COMPAT.md](docs/COMPAT.md) lists each ld64 load command, driver flag and semantic behavior with its status, the milestone that shipped it, and its fixture. Flags that arrive in later milestones (`-order_file`, `-ObjC`, TLV, LTO execution) are rejected with a clear message today.

## Status

> [!NOTE]
> Peregrine is a pre-1.0 project (v0.15.0) whose milestone stream follows the architecture doc: M6 (ICF, veneers, legacy fixups, Stage A caches) and M7 (versioned caches, build-system surface, the ≥ 98% compatibility suite, fuzzing at scale) shipped the in-tree scope; M8 shipped the resident + incremental foundations — the `pgrd` resident server with its persistent POI session, the reverse reference index, the insertion-stable import table, and slack-aware layout with the §7.3 fallback ladder; M9-v1 ships the in-place incremental relink engine — the versioned link record, the span-diff patch planner, the clone-and-patch output path with the merged-hash CodeDirectory rebuild, slack anchors, `-incremental`/`-incremental-verify`, and the byte-identity contract (tests + per-link audit); M9 tier 2b ships the per-symbol change-propagation planner — the record's section-digest table (content + symbol records) and the relink planner's propagation gate, which scopes every content change through the M8 reverse reference index and falls back when the span diff escapes the scope; M9 tier 2 ships the segment-relayout patch tier — the §7.3 ladder's middle rung executes (a slack overflow within the bound, or an outgrown `__LINKEDIT` reservation, patches the moved suffix through the record's v4 output-section content digests instead of falling back) — and the M9 GA hardening pass ships the ladder's shrink rung (an unsigned relink has no signature boundary to anchor the tail, so a symtab/string-pool shrink now patches through the relayout tier with the clone truncated instead of falling back) plus the seeded randomized edit gate (the engine-level and end-to-end `-incremental-verify` walks; `PGR_RANDOMIZED_STEPS` sizes the walk, 2000 sequences × 5 steps being the roadmap's 10⁴ GA profile for the decision rig). The target is arm64-apple-darwin only — `CPU_TYPE_ARM64`, little-endian, 16 KiB segment congruence — producing `MH_EXECUTE`, `MH_DYLIB` and `MH_BUNDLE` images; chained fixups serve macOS 12.0+ targets, and older deployment targets (or `-no_fixup_chains`) get classic `LC_DYLD_INFO_ONLY` rebase/bind streams. The host side is platform-independent: CI builds and runs the full test suite on Linux x86_64 and macOS aarch64. Performance claims stop at the dev-sandbox baselines in docs/BENCHMARKS.md — the hardware gates against `ld64.lld` on Apple Silicon (including M8's resident-relink gate and M9's §7.3 relink targets) are specified but not yet measured, the M8 warm-relink bench is recorded honestly as a wash on the Pass 2/3-bound sandbox corpus, and the M9 incremental bench records both the bytes-written win (~1% of an 8 MiB image per one-function edit, ~13% per slack-overflowing edit through the segment-relayout tier) and the ext4-clone wash. LTO object execution, compact-unwind synthesis, `-order_file`, TLV and ObjC/Swift semantics beyond section pass-through stay on the roadmap; M9 tier 2c ships the incremental resolve’s decision core — the snapshot-backed reuse of Pass 2’s winners scoped by the propagation seeds and equality-gated against the full resolve — and the M9 GA record-side wiring ships the decision core's delivery path (the record's v5 resolution-snapshot section, the relink's Pass 2 planning through the recorded decisions, refusing to the full resolve when the reuse shape moves); the resident fusion wire rung puts both incremental halves on the daemon wire (protocol v3: the previous record in, the refreshed record and patch outcome out) and runs the §7.3 ladder inside the resident session — warm POIs pipeline the relink, the patched bytes cross the wire, the client writes the file, and a daemon-internal fallback renews the record so the cycle survives; the audited fusion rung (wire v4) completes the audit's move: the daemon serves `-incremental-verify` — byte-identity against the reference emit plus the strict verifier, divergence healed in memory, verdict on the wire, nothing written on a failing verdict; the §7.2 output-residency rung (wire v5) closes the last deferred fusion item — the session-resident output buffer: every served image becomes resident output state (content-hash keyed, ceiling-covered), the previous output stops re-crossing the wire, a patched relink's reply is the changed 16 KiB-tile stream (`pgr_emit::incremental::TilePatch`) instead of the image, an untouched relink ships nothing, and the client hash-verifies its replay before the atomic write (the daemon still never touches the filesystem). M10 rung 1 ships the `-r` relocatable output: Passes 1–2 stop short of the segment layout and `pgr_emit::build_object_image` assembles the `MH_OBJECT` the pipeline itself consumes as an input — sections merged at their declared alignments, relocation entries preserved and re-pointed at the output symbol table (`ADDEND`/`SUBTRACTOR` pairs re-emitted in decode order), the symtab grouped locals/winner-backed globals/open undefineds with its `LC_DYSYMTAB` subranges, and undefined externals left open by design; the two-step self-consumption link (`pgr -r a.o b.o -o out.o`, then `pgr out.o -o exe`) is a test gate, the verifier carries the object contract (no fixups/signature on `MH_OBJECT`, every relocation entry bounds-checked), and `pgr-emit`'s `object` bench plus the `relocatable_link` consumer example ride along. M10 rung 2 ships the platform plumbing — `-platform_version` accepts the five linked platforms (`macos`, `ios`, `tvos`, `watchos`, `visionos`; unknown names refuse with the surface in the hint, and an SDK older than the deployment target refuses at parse time), the layout's chained-fixups gate is per-platform (`chained_fixups_min_minos`: macOS 12.0 / iOS 15.0 / tvOS 15.0 / watchOS 8.0 / visionOS 1.0 — below the floor the M6 classic opcode streams encode the same fixups), the verifier's build-version gate checks the *declared* platform (unknown constants are errors, `sdk < minos` is an error, the five platforms verify strict-clean), `pgr_format::PLATFORM_VISIONOS` crosschecks against the vendored headers' `PLATFORM_XROS`, and the `platform_matrix` consumer example plus the `platform` bench ride along. M10 rung 3 makes the encoding decision a consumer seam: slice 1 named it in the library (`pgr_core::platform::FixupEncoding::for_target` reads the same per-platform floor table the layout encodes — one table, two readers — with a tracing event on the decision and the `platform_floor` example rendering the below-floor advisory as miette help text); slice 2 crosses the surface: `pgr --print-fixup-encoding <platform> <min> <sdk>` (and `pgr_driver::fixup_encoding_report`) answers the build system's before-the-link question with the `-platform_version` refusals and a miette advisory on below-floor rows, the verifier's build-version gate reads the same canonical floor table (`pgr_format::consts::chained_fixups_floor` — one table, three readers) and refuses chained fixups below the declared platform's floor with the new `fixups_floor` code, the fixture builder takes its build version as a knob (`ImageBuilder::set_build_version` — no more post-build repatching), and the `encoding_query` consumer example plus the verifier's first bench (`verify_platform_floor`) ride along. M10 rung 4, slice 1 opens the arm64e read side: `pgr_format::fixups::ChainWordArm64e` names the `DYLD_CHAINED_PTR_ARM64E` word family (the two-bit bind/auth discriminator rides bits 62/63, `next` counts 8-byte strides), `pgr_fixtures::PointerFormatKind::Arm64e` builds the shapes (unauth rebases carry VM-address targets, auth words carry the diversity/key PAC triple), and the verifier's dyld chain-walk, `__chain_starts` mirror and slot-count gates accept the format — the Pass-3 producer encoding and the driver surface are the rung's next slice. M10 rung 4, slice 2 ships that producer: `pgr_core::fixups::FixupPointerFormat` names the word family and `plan_fixups_with_format` encodes it (the default `Offset64` stays byte-identical to the M2 planner — the §7.2 lock holds; `Arm64e` swaps the rebase target to a VM address, strides `next` in 8-byte units, and declares pointer format 1 in the payload records and the `__chain_starts` mirror, with the import table and its M9 anchor untouched), the driver surface names it (`-fixup_chains_format offset64|arm64e`, refusing the combinations that cannot carry the family — the classic opcode path, the resident session, `-r` — with the fix in the message), the daemon wire mirrors the family faithfully (v6 tail byte), and the `arm64e_producer` consumer example plus the planner bench ride along. M10 rung 4, slice 3 closes the family's named target — the **authenticated** words: the same Pass-3 planner takes a `pgr_core::fixups::FixupAuth` policy (`plan_fixups_with_auth`), auth rebases carry the 32-bit runtime offset dyld adds to the preferred load address plus the diversity/addrDiv/key PAC triple, auth binds carry the ordinal and move their whole addend into the import entry (the auth bind word has no addend field — the M2 split's one named exception, and the M9 anchor appends the signed key without renumbering), the 64_OFFSET family refuses a policy outright (no auth discriminator to set), an empty policy plans byte-identically to the slice-2 planner, the verifier's dyld walk has read these words since slice 1, and the `fixup_chains_auth` consumer example renders the refusal as miette help text while the `arm64e_auth` bench variant rides the same corpus. M10 rung 4, slice 4 closes the rung's named deferral — the M3 pair gate goes family-blind: the two-level bind replay decodes each segment through its own `pointer_format` (`ChainWord64` under the 64 families, `ChainWordArm64e` under arm64e) and strides by the family's `chain_stride` (4 or 8 bytes), so an arm64e executable binding a name its dylib does not export is refused where slice 3 left it passing silently; the `arm64e_pair` consumer example renders the refusal as miette help text and the pair-replay bench variant rides the same corpus. M10 rung 4, slice 5 makes the family honest below the deployment floor: an explicitly named `-fixup_chains_format` (either spelling) refuses when the `-platform_version` target sits below the platform's chained-fixups floor — the layout would plan the classic opcode streams and the named family would never reach the image (a refusal, never a silently dropped knob) — while the flag-less default keeps the documented silent fallback, the refusal renders its fix as miette help text, the `chain_format_floor` consumer example walks the whole story, and the slice's sweep heals the rung's fixture debt (the auth slots register their imports and ride the indirect symbol table) plus the docs drift the audit found.
